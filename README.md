# WhatsApp Personal Automation

使用 **Whapi.Cloud 关联设备**接入 WhatsApp 个人号的本地 Python PoC：指定私聊/群的新消息 → SQLite 去重 → 供需字段识别 → 本地撮合候选；指定单一私聊可开启限时、限条数自动确认回复。

Python 3.10+，全部使用标准库；无需 `pip install`，不调用大模型。独立于任何业务系统。

## 5 分钟启动

```sh
git clone https://github.com/xemaya/whatsapp-personal-automation.git
cd whatsapp-personal-automation
python3 -B server.py
```

打开 **http://127.0.0.1:8797/**。macOS/Linux 也可运行 `./start.sh`，Windows 使用 `py -3 server.py`。

先点「回放测试样例」即可离线体验：9 条合成消息、2 组撮合候选。样例不发送到 WhatsApp，测试也不会调用真实 Whapi。

真实联调需要你自己的 Whapi 账号、已扫码的频道和 API Token。频道服务的费用/额度以 Whapi 控制台为准，本项目不会购买或续费。

## 接一个个人号

1. 在 [Whapi 控制台](https://panel.whapi.cloud/) 注册账号，创建频道；用你的 WhatsApp「关联设备」扫码。这里使用关联设备方案，不要求 WhatsApp Business 账号，也不属于 Meta 官方 Cloud API 接入。
2. 在本机页面填写 Channel ID、API Token，点「读取频道与群列表」。Token 只驻留当前服务进程内存，不写文件或浏览器存储；重启需重新填。
3. 填写一个已核对、同意测试的联系人名称和国际手机号（不带空格），或其 `@s.whatsapp.net` 私聊 ID，点击启用该联系人。私聊白名单只有一个，与群白名单互斥。
4. 让对方在启用后发送：`求购书桌，伦敦，预算60英镑`。点击「读取选定对话新消息」，看到实际接入消息与 `poll` 回执后，才能判定读取成功。
5. 要自动回复，选一档额度并点「启动限额自动回复」。默认 **30 分钟 / 最多 10 条**；也提供 10 分钟 / 3 条和 60 分钟 / 20 条。界面可立即停止。

自动回复会先处理最近一小时内最新的、已导入且尚未尝试回复的有效供需消息；之后每轮读取完成约 15 秒再检查新消息。每条入站消息最多尝试回复一次，当前进程重启后默认不恢复运行。

示例回复：

> 我是 WhatsApp 自动化测试助手。已识别：求购 / 书桌 / 伦敦 / 预算 60 GBP。这条信息已记录在本机测试台，目前尚未完成买卖双方撮合。若识别有误，请发一条更正。

**这版自动回复是供需确认规则，不是通用聊天机器人。** 只有识别为出售/求购且商品明确的有效文字消息会进入回复路径；闲聊、多商品歧义、结束状态、图片和语音不会自动回复。自行发送的消息、非白名单联系人和演示消息不会触发真实发送。

## 能力与边界

| 能力 | 当前实现 |
|---|---|
| 个人号接入 | Whapi 关联设备；项目本身不实现 WhatsApp 协议或托管账号 |
| 私聊读取 | 指定一个手机号联系人，保存白名单之后的新消息 |
| 群读取 | 最多选择 3 个获准测试的群，每群每轮最多 5 页，每页 100 条 |
| 群撮合 | 同群、不同发言人的出售/求购候选，仅在本机展示 |
| 自动回复 | 仅指定单一私聊；时限、尝试条数、读取次数均有限额 |
| 模型/多轮对话 | 未接入；规则支持中英文供需、若干商品、6 个城市、币种及 iPhone 型号 |
| Webhook | 独立 8798 接收端与秘密 Header；公网隧道和供应商设置需自行配置，未随项目启用 |
| 图片/语音 | 只保留必要附件元数据/说明，不下载或识别媒体 |

手动消息查询每服务进程最多 20 次。自动查询独立预算为 `ceil(时限秒数 / 15) + 5` 次（默认 125 次）；预算耗尽、时间到、发送尝试数达到上限、联系人/频道变更、读取或发送异常都会停止。

发送前先将入站消息 key 写入 `auto_replies`。`accepted` 仅表示 Whapi 返回 `sent=true` 和消息 ID，不代表收件人送达或已读。超时、失败或结果不明确会停止，不自动重试；`attempting` 也不会在重启后自动重发。停止不会撤销已提交或正在进行的网络请求，默认网络超时 20 秒。

## 测试

```sh
python3 -B -m unittest test_poc test_autoreply -v
# 若安装 Node，可额外检查浏览器脚本语法
node --check static/app.js
```

64 项测试，覆盖规则冲突、白名单、去重、启用时间、私聊身份、自己消息过滤、HTTP 边界、发送额度/到期/停止以及未知结果不重试。测试使用合成数据和模拟供应商，不会向真人发送。

开发时曾完成个人号真实私聊读取、规则识别和自动回复的供应商受理验证。公开仓不含真人数据或回执；接手人仍需用自己的账号重新验收。**真实群收消息、多成员撮合和 Webhook 连续运行尚未完成现场验收。**

## 数据与运行

- `runtime/` 首次运行自动生成，目录权限 700。保存 SQLite 消息、白名单、供需结果、回执与 webhook secret；该目录、截图、日志、`.env` 全部被 Git 忽略。
- 管理服务绑定 `127.0.0.1:8797`，仅本机使用；不要公开管理端口。可选回调服务绑定 `127.0.0.1:8798`，只处理鉴权后的 `POST /webhook`。
- 读取仅访问固定 `gate.whapi.cloud` 的健康、群列表及白名单消息端点；自动发送只调用 `/messages/text`，目标必须是当前唯一私聊。通用 `/api/send` 固定拒绝。
- 手动拉取不保证发现旧消息后续的编辑/撤回；相关状态机有模拟测试，供应商实际事件差异仍需真实回调验证。
- 没有自动加群、账号创建、群发或生产集成。只连接本人持有的账号及获准测试的对话；个人号第三方自动化有平台限制风险，正式使用前自行核对适用条款。
- `Ctrl+C` 停服务；页面「立即停止」仅关自动回复，「清除本机 Token」会断开本机调用权限。撤销供应商关联设备请在 WhatsApp 手机端完成。

端口被占用时：

```sh
python3 -B server.py --port 8897 --ingress-port 8898
# macOS/Linux 可加 --runtime 指向另一个本机私有目录
```
